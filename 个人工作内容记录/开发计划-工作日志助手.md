# 工作日志助手（Web 版）开发计划

> 版本：v1.0 ｜ 状态：**已完成开发与上线验证**
>
> 一句话定位：**一个属于我自己的、简单好用的每日工作记录工具，AI 帮我整理润色，月底一键生成汇报材料。**
>
> 架构/目录/接口与运维细节见代码仓 `工作日志助手/docs/`（架构设计、开发指南、部署运维手册）。

## 1. 产品概述

### 1.1 解决什么问题

| 痛点 | 本产品如何解决 |
|------|----------------|
| 每天工作内容随手记，月底翻聊天记录/便签找素材很痛苦 | 每天一条结构化记录，按月自动归档 |
| 写出来的记录口语化、零散，不适合直接交汇报 | AI 一键"整理润色"，转成正式汇报表达 |
| 月度考核填表时需要重新回忆整月工作 | 月度汇总：AI 按月聚合记录，生成月报初稿 |
| 市面产品要么太重（项目管理工具），要么没 AI，要么数据不在自己手里 | 自己开发：轻量 + AI + 数据自主（本地/Docker 自托管） |

### 1.2 核心用户与场景

- **用户**：多用户设计——自己为主，支持注册多个账号，数据互相隔离，将来同事/家人可各开账号。
- **场景 A（每天 3 分钟）**：下班前打开网页/手机，随手记今天做了什么（可以很口语化），保存。
- **场景 B（AI 整理）**：对某天的记录点一下"AI 整理"，得到结构化、书面化的版本，可手动微调。
- **场景 C（月底 30 分钟变 5 分钟）**：进入"月报"页面，选择月份，AI 汇总全月记录 → 生成月度汇报初稿 → 复制/导出到公司考核表。

### 1.3 参考市面产品

借鉴对象：flomo（轻量记录）、Notion AI（AI 润色）、滴答清单（快捷输入）、飞书妙记（AI 总结）。差异点：**专为"工作记录→月度汇报"这一条链路设计，不做无关功能**。

## 2. MVP 功能范围

### P0 — 没有就不能上线

| 模块 | 功能点 |
|------|--------|
| 账号 | **多用户**：注册 / 登录 / 退出；密码登录即可；登录态保持（记住我）；数据按用户隔离 |

## 3. 技术方案

### 3.1 技术栈（主流 JS 全栈，个人可维护）

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue 3 + Vite + TypeScript | 上手快、生态成熟、适合中小项目 |
| UI 组件 | Element Plus（按需引入）+ 自定义主题 | 覆盖表单/弹窗等基础组件，自定义主题对齐海螺设计规范 |
| 响应式 | CSS Flex/Grid + 移动优先断点 | PC / 手机同一套代码 |
| 后端 | Node.js + Express（或 NestJS） | 与前端同语言，单人开发成本低 |
| 数据库 | SQLite（MVP）→ 可平滑换 PostgreSQL | 零运维、单文件备份，数据规模个人用绰绰有余 |
| ORM | Prisma | 类型安全、迁移方便 |
| AI 接入 | OpenAI 兼容接口（自定义 base-url `/v1` + Key + 模型名，设置页可配） | 不绑定任何服务商：OpenAI / DeepSeek / 通义 / Kimi / 智谱 / Ollama 均可，用户在后台自行配置和切换 |
| 认证 | JWT（httpOnly Cookie） | 简单够用 |
| 部署 | Docker + docker-compose | 一键起 web + api + 数据卷 |

### 3.2 系统架构（MVP 极简单体）

```
┌─────────────────────────────────────┐
│   前端 SPA（Vue3，PC/手机响应式）      │
└──────────────┬──────────────────────┘
               │ HTTPS / JSON
┌──────────────▼──────────────────────┐
│   后端 API（Node.js 单体服务）        │
│   ├─ auth    认证模块                │
│   ├─ entries 记录 CRUD + 搜索        │
│   ├─ ai      AI 整理/汇总（调 LLM）   │
│   └─ reports 月报生成与导出           │
├─────────────────────────────────────┤
│   SQLite（数据卷持久化）              │
└─────────────────────────────────────┘
               │
        外部 LLM API（可配置）
```

### 3.3 核心数据模型（初稿）

```
User        { id, username, password_hash, created_at }   // 多用户
Entry       { id, user_id, entry_date, raw_content, polished_content,
              polished_at, tags[], word_count, created_at, updated_at }
Report      { id, user_id, year_month, content(md), generated_at, status }
AiConfig    { id, user_id, base_url(/v1), api_key(加密), model,
              formality(简洁/标准/详细) }
```

> 多用户要点：所有业务表带 `user_id` 并在 API 层强制按当前登录用户过滤；注册默认开放（可在配置中切换为邀请制）。

### 3.4 AI 提示词设计（核心体验）

- **单条整理**：System Prompt 约束——"你是工作汇报助手，把口语化记录改写为书面化的工作内容条目；保留事实，不虚构；突出动作与成果；输出分条列表"。提供"正式程度"选项：简洁 / 标准 / 详细。
- **月度汇总**：按日期注入全月记录 → 生成月度总结。无固定公司模板，输出结构以"把做了什么事写清楚"为目标：本月主要工作（按事项分条，每条说清做了什么、结果如何）/ 重点成果 / 问题与改进 / 下月计划。每用户可在设置中自定义补充要求（P1）。
- API Key 加密存储；AI 调用失败时给出明确提示并保留原文。

## 4. UI/UX 设计方案

### 4.1 设计基准

遵循《海螺UI设计规范 - 白色 v1》（已获取规范全文），全部设计约束以 **Design Token** 沉淀为 CSS 变量（`tokens.css`），全站只引用变量，组件库（Element Plus）按 Token 定制主题变量，做到"改一处、全站生效"。

### 4.2 Design Token（已从规范提取）

#### 色彩系统（Color）

| Token | 色值 | 用途 |
|-------|------|------|
| --color-primary | `#0A5CFF` | 主色：主按钮、链接、选中色块 |
| --color-primary-light | `#488BFF` | 强调文字 |
| --color-success | `#00A870` | 成功反馈 |
| --color-danger | `#E34D59` | 错误/失败反馈 |
| --color-warning | `#ED7B2F` | 次要指引 |
| --color-text-main | `#222222` | 主要文字、重要标题 |
| --color-text-sub | `#666666` | 次要文字、辅助 |
| --color-text-placeholder | `#999999` | 占位/辅助/禁用文字 |
| --color-divider | `#DDDDDD` | 分割线、边框 |
| --color-bg-page | `#F5F5F5` | 页面背景、表头底色 |
| --color-bg-card | `#FFFFFF` | 卡片、弹窗背景 |
| --color-bg-disabled | `#CCCCCC` | 禁用控件底色 |
| --color-bg-selected | `#959595` | 选中色块 |
| --accent-colors | 02BFCA / FF6439 / FEB031 / 7C42E3 / 0C5DFF / 1CC519 | 点缀色阶（尽量避免，用于数据强调） |

#### 字体规范（Typography）

| 类别 | 字号 | 行高 | 色值 | 场景 |
|------|------|------|------|------|
| 重要标题 | 22px | 30 | #222222 | 页面大标题、弹窗标题、重要数据 |
| 一级标题 | 18px | 26 | #333333 | 模块标题、导航、内容标题 |
| 二级标题 | 16px | 24 | #333333 | 列表标题、分组名、表格表头 |
| 正文 | 14px | 22 | #333333 | 表单标签、表格内容、普通描述 |
| 辅助文字 | 12px | 20 | #666666 | 说明文案、时间戳、占位提示 |
| 极弱文字 | 12px | 20 | #999999 | 禁用、不可用状态 |

- 字体族：中文 `微软雅黑 (Microsoft YaHei)`，英文/数字 `Arial`，不自定义字体。

#### 边距/圆角/布局（Spacing & Radius）

| Token | 值 | 说明 |
|-------|----|------|
| --radius-sm | 4px | 面板、按钮、输入框、普通组件 |
| --radius-lg | 6px | 弹窗 |
| --padding-panel | 24px | 所有卡片/面板内部四周统一 24px，不随意改 |
| --space-md | 16px | 弹窗内容区内部组件间距 |
| --titlebar-height | 64px | 业务系统模块顶部标题栏高度 |
| --modal-titlebar | 40px | 弹窗标题栏高度 |
| --modal-footer | 64px | 弹窗底部按钮区域高度 |
| --toast-top | 90px | Toast 距浏览器上边距离 |

#### 图标（Icon）

- 风格：**线性（描边 1.5–2px）或简洁面性**；禁止卡通/写实复杂图标；**导航优先面性图标**。
- 尺寸：18×18px（表格内、导航展开）、24×24px（工具栏、导航收起）、36–42px（大图标场景）。
- 颜色：默认继承文字色；激活用主色；警示用对应功能色。

#### 按钮（Button）

- 高度：标准 32px、矩形 36px；两侧最小内边距 16px；图标与文字间距 10px。
- 状态：默认/移入/按下/禁用；**主按钮按下出现 2px 边框，次要按钮不需要**。
- 类型：标准主按钮、次要按钮、图标按钮、纯图标按钮。

#### 弹窗（Modal）& 反馈

- 圆角 6px；打开带全屏遮罩 `#000000` 透明度 50%；尺寸自适应不强制固定。
- 布局：标题栏 40px，内容四周 24px、内部 16px，底部按钮区 64px。
- 类型：普通表单弹窗、确认删除类弹窗。
- Toast：页面顶部距上边 90px，自动消失；正向绿/错误红/中性蓝；**重要删除操作必须用确认弹窗，不用 toast**。

#### 通用组件（在 Element Plus 上定制实现）

输入框/下拉统一 4px 圆角、边框 #DDDDDD、占位 #999999；表格表头 #F5F5F5、分割线 #DDDDDD；分页支持 10/20/30/40 条每页；表单 label 用正文 14px、提示用辅助文字 12px；禁用状态文字 #999999、底色 #CCCCCC。

### 4.3 页面清单（MVP 共 5 页）

| 页面 | PC 布局 | 手机布局 |
|------|---------|----------|
| 登录/注册 | 居中卡片 | 居中卡片 |
| 今日记录（首页） | 左侧：今日记录编辑卡（大输入区 + AI整理按钮）；右侧：最近记录列表 | 单列：先编辑卡，下拉为最近记录 |
| 记录列表/搜索 | 顶栏月份切换 + 搜索框；按日分组的时间流 | 月份选择器 + 搜索；时间流 |
| 月报页 | 月份选择 → 生成按钮 → 左文右预览 | 逐步式：选月份→生成→查看/导出 |
| 设置 | AI 配置（接口地址 `/v1`、API Key、模型名、正式程度）、修改密码、数据导出 | 同（纵向排列） |

> 此产品为业务系统风格，套用"业务系统框架"：顶部 Tab 页签 + 左侧主导航（展开/收起，收起只显示 24px 图标）+ 右侧功能内容区；面板内容四周统一 24px 内边距；模块顶部标题栏 64px。

交互原则：**记录 ≤ 3 次点击**；AI 整理结果显示对比视图（原文/整理后），用户确认后才覆盖；一切操作有 loading 态与错误提示；删除走确认弹窗。

## 8. 验收标准（MVP 完成定义）

- 手机浏览器和 PC 浏览器均可流畅完成"记一条 → AI 整理 → 月底生成月报 → 导出"全流程
- 断网/AI 失败时记录功能不受影响，数据不丢失
- 视觉与《海螺UI设计规范-白色 v1》一致
- Docker 一条命令可在全新服务器上启动
- 每日记录耗时 ≤ 3 分钟
