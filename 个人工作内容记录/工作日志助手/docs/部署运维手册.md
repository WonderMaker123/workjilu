# 部署运维手册

> 生产环境的拓扑、首次部署、日常更新、证书续期、备份恢复与故障排查。
> 服务器为共用主机，**80/443 由既有的宿主 Nginx 容器统一占用**，本应用以"加站点"方式接入，任何操作都不得影响上面的其他服务。

## 1. 生产拓扑

| 项 | 值 |
|---|---|
| 服务器 | 推荐 Linux 云服务器，Debian 12 / Ubuntu 22.04（建议 1GB+ 内存，小内存建议加 Swap） |
| 域名 | 自定义域名（如 worklog.yourdomain.com） |
| 证书 | Let's Encrypt，有效期 90 天，certbot 定时自动续期 |
| 代码目录 | `/opt/worklog`（含 `docker-compose.prod.yml`、`.env`） |
| 访问地址 | https://worklog.yourdomain.com |

容器与网络：

```
宿主 nginx 容器（若有宿主统一反代）
  配置目录 /etc/nginx/conf.d
  证书目录 /etc/nginx/certs
        │  server_name worklog.yourdomain.com → proxy_pass http://127.0.0.1:18081
        ▼
worklog-web   127.0.0.1:18081->80（Nginx：静态站 + /api → server:3001）
worklog-server 3001（仅容器网络，不对宿主暴露）
        │
        ├── 卷 worklog_worklog-data    → /app/data    （worklog.db 数据库）
        └── 卷 worklog_worklog-uploads → /app/uploads （照片）
```

本应用的反代配置：`/etc/nginx/conf.d/worklog.conf`
证书文件：`/etc/nginx/certs/worklog_cert.pem` 与 `_key.pem`
续期钩子：`/etc/letsencrypt/renewal-hooks/deploy/worklog-text.sh`（续期后自动复制证书并 `docker exec nginx nginx -s reload`）。

同主机还有其他业务（vertex :3000、portainer :9000、api.ldvx.de），互不相干，不要停/改 `nginx` 容器本身。

## 2. 环境变量

生产变量在 `/opt/worklog/.env`（权限 600，**不入库、不进镜像**），模板见项目根 `.env.production.example`：

| 变量 | 说明 |
|---|---|
| `JWT_SECRET` | 必填，`openssl rand -hex 32` 生成；换掉会导致所有登录态失效 |
| `ENCRYPT_KEY` | 可选，AI API Key 加密密钥；缺省回退 JWT_SECRET |

compose 内已固定：`NODE_ENV=production`、`PORT=3001`、`DATABASE_URL=file:/app/data/worklog.db`、`CORS_ORIGIN=https://worklog.yourdomain.com`。

## 3. 首次部署（换机器时照做）

```bash
# 0) 装 Docker（略），把项目源码放到 /opt/worklog（含 server/web、compose、.env）
cd /opt/worklog
umask 077 && echo "JWT_SECRET=$(openssl rand -hex 32)" > .env

# 1) 内存小就先加 swap（按需）
fallocate -l 2G /swapfile2 && chmod 600 /swapfile2 && mkswap /swapfile2 && swapon /swapfile2

# 2) 构建启动（先只绑 127.0.0.1:18081，无需证书）
docker compose --env-file .env -f docker-compose.prod.yml up -d --build
curl -s http://127.0.0.1:18081/api/health   # 期望 {"ok":true,...}

# 3) 在宿主反代加"仅 HTTP"站点（含 /.well-known/acme-challenge webroot），reload
#    参考模板改好 server_name 与 upstream 端口 (18081)
docker exec nginx nginx -t && docker exec nginx nginx -s reload

# 4) 签证书
apt-get install -y certbot   # 如未安装
certbot certonly --webroot -w /var/www/letsencrypt -d worklog.yourdomain.com \
  --non-interactive --agree-tos -m <你的邮箱>   # 建议带邮箱接收到期提醒

# 5) 复制证书到反代证书目录，换成 HTTPS 版 vhost 后 reload
cp -L /etc/letsencrypt/live/worklog.yourdomain.com/{fullchain.pem,privkey.pem} /tmp/
mv /tmp/fullchain.pem /etc/nginx/certs/worklog_cert.pem
mv /tmp/privkey.pem  /etc/nginx/certs/worklog_key.pem
# 放入正式 vhost 配置，配置续期钩子
docker exec nginx nginx -t && docker exec nginx nginx -s reload
```

> Cloudflare 若以后开启橙云代理，SSL/TLS 模式必须选 **Full (strict)**。

## 4. 日常更新代码

在本机改完代码、本地 `vue-tsc`/`tsc` 校验通过后：

```powershell
# 本机：打包（示例，排除依赖与产物）
tar -czf worklog-src.tar.gz --exclude=node_modules --exclude=dist --exclude=.git `
  --exclude='*.db' --exclude=.env --exclude=uploads server web docker-compose.prod.yml
scp -i <部署私钥> worklog-src.tar.gz root@<你的服务器IP>:/root/
```

```bash
# 服务器：解压覆盖 → 重建
tar -xzf /root/worklog-src.tar.gz -C /opt/worklog && rm /root/worklog-src.tar.gz
cd /opt/worklog
docker compose --env-file .env -f docker-compose.prod.yml up -d --build
# 含新迁移时，worklog-server 启动会自动 migrate deploy
docker logs -f worklog-server      # 确认 "All migrations ... applied" 与服务启动
```

只改了前端：只重建 `web`；只改后端：把命令末尾加 `server`。

## 5. 日常运维

```bash
# 状态 / 重启
docker ps | grep worklog
docker compose --env-file .env -f docker-compose.prod.yml restart server

# 日志
docker logs --tail=200 worklog-server
docker logs --tail=200 worklog-web
docker exec nginx tail -50 /var/log/nginx/access.log     # 反代日志在宿主卷

# 进容器 / 进数据库
docker exec -it worklog-server sh
docker exec -it worklog-server npx prisma studio # 不适用（未对外）；可用：
docker exec -it worklog-server node -e "const{PrismaClient}=require('@prisma/client');new PrismaClient().\$queryRaw\$('select count(*) c from Entry').then(r=>{console.log(r);process.exit(0)})"
```

证书：

```bash
certbot certificates                       # 查看证书与到期时间
certbot renew --dry-run                    # 演练续期（钩子也会被模拟）
```

## 6. 备份与恢复

有状态内容只有两样：**数据库卷**与**照片卷**。也可以在页面「设置 → 数据备份」导出 JSON（含记录/报告/AI 配置，照片文件不在 JSON 内）。

卷级备份（停服一致性要求低时可热备；稳妥起见先停 server）：

```bash
mkdir -p /opt/worklog/backup && cd /opt/worklog/backup
docker run --rm -v worklog_worklog-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/worklog-data-$(date +%F).tgz -C /data .
docker run --rm -v worklog_worklog-uploads:/data -v "$PWD":/backup alpine \
  tar czf /backup/worklog-uploads-$(date +%F).tgz -C /data .
```

恢复：把上面的 `tar czf` 换成 `tar xzf /backup/xxx.tgz -C /data` 重新起容器即可。建议把备份文件再拉回本地或异地，不要只留在同一台机器。

## 7. 故障排查

| 现象 | 排查 |
|---|---|
| 页面 502 | `docker ps` 看 worklog-server 是否在 Restarting；`docker logs worklog-server` 看堆栈。历史教训：缺迁移列（P2022）会让查询进程崩溃 |
| 502 但容器在跑 | `curl http://127.0.0.1:18081/api/health` 定位是 web 容器还是上游；再看反代 vhost 的 upstream 端口是否为 18081 |
| 改完代码没生效 | 镜像没重建（必须 `up -d --build`）；浏览器强刷（Ctrl+F5）排除 SW/缓存 |
| 证书签发失败 | 确认 80 能公网访问、`/home/web/letsencrypt` 挂载正确、域名 A 记录指向本机；`tail -50 /var/log/letsencrypt/letsencrypt.log` |
| 登录态频繁失效 | `.env` 的 `JWT_SECRET` 变了（重建容器/重新生成密钥会导致） |
| AI 请求失败 | 设置页"测试连接"先定位；服务端日志看上游返回；注意反代 120s、前端 90s 超时 |
| 构建 OOM（小内存机） | 确认 swap 已启用：`swapon --show`；构建时别同时跑重任务 |
| api.ldvx.de 等其他站点异常 | 与本应用无关，先看对应 upstream 端口是否有进程，勿动共享 nginx 容器 |

## 8. 下线/迁移清单

- 停服：`docker compose --env-file .env -f docker-compose.prod.yml down`
- 撤站点：移除对应 Nginx 虚拟主机配置后 `nginx -s reload`；证书可 `certbot delete --cert-name worklog.yourdomain.com`。
- 清数据（**不可逆**）：`docker volume rm worklog_worklog-data worklog_worklog-uploads`。
