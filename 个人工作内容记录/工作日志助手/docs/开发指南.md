# 开发指南

> 本地环境准备、日常开发命令、数据库迁移规范，以及"加一个功能"的完整链路。
> 架构与目录含义见 [架构设计](./架构设计.md)，上线/更新见 [部署运维手册](./部署运维手册.md)。

## 1. 环境要求

- Node.js ≥ 20（含 npm）
- Git
- 编辑器推荐 VS Code：Volar（Vue 官方插件）、ESLint/Prettier 可选
- 不需要本地数据库，SQLite 由 Prisma 自动建文件
- 想用 AI 功能：自备一个 OpenAI 兼容服务（如 DeepSeek）的 API Key，在页面「设置 → AI 配置」里填即可

## 2. 首次启动

```powershell
# 后端（终端 1）
cd 工作日志助手/server
copy .env.example .env          # Windows；macOS/Linux 用 cp
npm install
npx prisma migrate deploy       # 按 migrations 建本地库 dev.db
npm run dev                     # http://localhost:3001，ts-node-dev 热重载

# 前端（终端 2）
cd 工作日志助手/web
copy .env.example .env
npm install
npm run dev                     # http://localhost:5173
```

浏览器开 http://localhost:5173 ，注册账号即可使用（数据保存在 `server/prisma/dev.db`）。

### 常用命令

| 作用 | 目录 | 命令 |
|---|---|---|
| 前端开发 | web | `npm run dev` |
| 前端类型+构建校验 | web | `npx vue-tsc --noEmit` 和 `npm run build` |
| 后端开发 | server | `npm run dev` |
| 后端编译校验 | server | `npm run build`（即 `tsc`） |
| 生成/执行迁移 | server | `npx prisma migrate dev --name <名字>` |
| 只重新生成 Client | server | `npx prisma generate` |
| 看库内容 | server | `npx prisma studio` |
| 本地容器整体跑 | 项目根 | `docker compose up -d --build` |

后端环境变量（`server/.env`）：`PORT=3001`、`JWT_SECRET`、`JWT_EXPIRES_IN=7d`、`DATABASE_URL=file:./dev.db`、`CORS_ORIGIN=http://localhost:5173`、可选 `ENCRYPT_KEY`（API Key 加密密钥，缺省回退 JWT_SECRET）。

前端构建期变量（`web/.env`）：`VITE_API_BASE=/api`；dev 代理目标可用 `VITE_PROXY_TARGET` 覆盖。

## 3. 数据库迁移规范（最重要）

**只认 migrations，禁止用 `db push` 代替迁移。** 曾经因为照片字段只改了 schema 没生成迁移，线上启动后缺列导致登录即 502。

标准动作：

```powershell
cd server
# 1. 改 prisma/schema.prisma
# 2. 生成迁移（会同时应用到本地 dev.db 并重新生成 client）
npx prisma migrate dev --name add_entry_photos
# 3. 确认 prisma/migrations/<时间戳>_<名字>/migration.sql 内容
# 4. schema.prisma + 新迁移目录一起提交
```

约定：

- 迁移只增不改不删；已经推到线上的迁移文件不要修改。
- 本地若出现 schema 已改但没迁移的状态，`prisma migrate status` 能查出来。
- 线上容器启动时 `docker-entrypoint.sh` 自动执行 `prisma migrate deploy`，所以**部署带迁移的代码后会自动升级数据库**。
- SQLite 没有独立 JSON/日期类型：数组统一存 JSON 字符串（参考 `Entry.tags/photos`），读取后用 `JSON.parse` 兜底解析。

## 4. 加一个功能的标准链路

以"给记录加工时（小时）字段并在仪表盘统计"为例（这是待办项，可照此实现）：

1. **模型**：`server/prisma/schema.prisma` 的 `Entry` 加 `workHours Float?`。
2. **迁移**：`npx prisma migrate dev --name add_entry_work_hours`。
3. **后端路由**：
   - `routes/entries.ts` 的创建/更新入参白名单与 zod 校验里加 `workHours`；
   - `routes/stats.ts` 聚合里加本月工时合计。
4. **前端接口层**：`web/src/api/entries.ts` 的 `Entry` 接口和 create/update 参数加字段；`api/stats.ts` 的 `StatsOverview` 加字段。
5. **页面**：`TodayView.vue` 加输入项；`DashboardView.vue` 展示合计。
6. **自测**：走一遍"建记录→改记录→看统计"，再跑下面的提交前校验。

纯前端功能（无新数据）只做第 4～6 步；纯接口能力则不需要第 4～5 步之外的页面。

## 5. 编码约定

- 语言：TypeScript 全开 strict；前端组件统一 `<script setup lang="ts">`。
- 命名：文件/变量小驼峰，组件与 View 大驼峰，后端路由文件与资源同名，迁移用"动词+对象"（`add_entry_photos`）。
- 前端不直接 `axios(...)`：统一走 `lib/http.ts` 实例与 `api/` 封装；成功返回 `res.data`，错误已全局提示。
- 后端：
  - 路由保持薄：参数校验 → 调 Prisma/lib → 返回 JSON；复杂逻辑下沉到 `lib/`。
  - 所有数据查询带 `userId`；用 `AuthRequest`（`middleware/auth.ts`）取当前用户。
  - 入参校验用 zod（已在依赖里）；文件操作防路径穿越（参考 `lib/photos.ts`）。
- 样式：颜色/间距/圆角/字号用 `assets/tokens.css` 的 CSS 变量；Element Plus 主题覆盖写在 `assets/element-theme.css`，不要内联魔数。
- 文案：界面与报错均中文；不虚构公司业务、资质、数据。
- 品牌露出保持克制：角落与落款级别（登录页、侧栏、关于、报告抬头/落款）。

## 6. 提交前自查

```powershell
cd server && npm run build          # 0 error
cd ../web && npx vue-tsc --noEmit   # 0 error
cd ../web && npm run build          # 产物正常
```

- 涉及新环境变量：同步更新 `server/.env.example`、`web/.env.example` 与部署手册。
- 涉及数据结构：确认迁移文件已生成且内容正确。
- 涉及新页面：已注册路由、需要时加导航、未登录访问会跳登录页（路由守卫自动处理）。
- 涉及 AI 提示词：保持运维实施岗视角，输出中文书面语。

## 7. 常见问题

- **本地 5173 打开接口 502/网络错误**：后端 3001 没起，或 `VITE_PROXY_TARGET` 指错。
- **Prisma 报 "did not initialize yet"**：没生成 client，执行 `npx prisma generate`。
- **容器里 Prisma 报 libssl/engine 错误**：后端镜像必须是 `node:20-bookworm-slim`，不要换 alpine。
- **改了字段后报 P2022 column does not exist**：缺迁移，按第 3 节补。
- **PWA 改动不生效**：开发环境不注册 SW；需 `npm run build` 后用容器/静态服务器验证。
- **每日提醒不弹**：提醒依赖页面保持打开（浏览器标签存活着）。
